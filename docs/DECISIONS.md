# Decisions

Established project decisions. Change one only with owner approval. When one changes, edit its entry and note
what replaced it and when. Implementation-level rationale (timestep, tone mapping, asset folders, input design)
lives in [`ARCHITECTURE.md`](ARCHITECTURE.md).

| # | Decision | What it means in practice | Since |
|---|---|---|---|
| D1 | **Browser-first game** | Desktop Chrome/Edge first; Firefox/Safari kept reasonable. Since Phase 3 also phone and tablet browsers (iPhone Safari, Android Chrome) from the same build (D15). Deploys as a static site. No backend, database or accounts in Phase 1. | 2026-09-23 |
| D2 | **TypeScript and Three.js** | Strict TypeScript; rendering with three.js (WebGL 2). No Unity, Unreal, Godot, React or React Three Fiber without owner approval. | 2026-09-23 |
| D3 | **Vite for development and build** | `npm run dev` and `npm run build`; Vitest for unit tests. | 2026-09-23 |
| D4 | **Simple DOM-based interface** | HTML/CSS overlays. Markup lives in `index.html`, behaviour in `src/ui/`. No UI framework. | 2026-09-23 |
| D5 | **Stylized animated-film presentation with anime-inspired expression** | Warm, soft and cozy. Not photoreal, not chibi, not crude low-poly. Moke stays clearly dog-like and recognizable as *Moke*. | 2026-09-23 |
| D6 | **Small Phase 1 vertical slice before expanding the world** | One living room with polished movement, camera and interactions before any other rooms or areas. | 2026-09-23 |
| D7 | **Moke's visual model stays separate from controller/gameplay logic** | Swapping the placeholder dog for `moke.glb` must not require changes to movement, camera, physics, interactions, pickup or scent. | 2026-09-23 |
| D8 | **Private Moke photographs are development-only** | `reference/moke/` is git-ignored and never bundled, served, uploaded, modified or deleted. | 2026-09-23 |
| D9 | **Claude Code and Codex work sequentially** | Never simultaneously on overlapping files. Each session starts from Git and `docs/CURRENT_STATE.md`. | 2026-09-23 |
| D10 | **The repository and its documentation are the source of truth** | Not either agent's chat history. Status, decisions and handoff notes live in `docs/`. | 2026-09-23 |
| D11 | **Rapier for physics, starting in Milestone 2** | Owner approved it. In use since Milestone 2 (`@dimforge/rapier3d-compat` 0.20, lazy-loaded). One collision world for Moke now and, later, the toys. | 2026-09-23 |
| D12 | **Moke is built in code and modelled on the real Moke, softly stylized** | `ToonMokeVisual` replaces the old placeholder. First pass (2026-09-24) followed an anime illustration (cel shading, ink outlines, pointed tufts, big brown eyes, blush, "w" smile). The owner then asked for "less jagged, more like the real dog" (same day), which replaced it: curly rounded coat with soft crease shading, soft neutral-grey shading, a thin soft silhouette line, realistic dark eyes, black button nose on a mustached muzzle, no blush or drawn smile. Refines D5, keeps D7 (a `moke.glb` could still replace it via `createMokeVisual()`). **Since Phase 2 it's the stand-in and permanent fallback; the final character is `moke.glb` (D14).** | 2026-09-24 |
| D13 | **Hosted on GitHub Pages; the repository is public** | Owner request (2026-09-24), to play on other machines. `.github/workflows/deploy-pages.yml` tests, builds (with the private-photo leak check) and publishes `dist/` to https://christopher-013.github.io/im-dog/ on every push to `main`. The owner chose to make the repo public rather than use a paid plan; the history was audited first (no photos, secrets or private files). | 2026-09-24 |
| D14 | **The final Moke is a rigged, animated `moke.glb` with fixed conventions and one authoritative scale** | Set in Phase 2 per the owner's brief ("Make Moke actually Moke"). **Scale** lives in one place, `MOKE_CHARACTER` (`config/mokeCharacter.ts`: shoulder 0.28 m, eyes 0.33 m, head top 0.43 m, an estimate until the real Moke is measured); the camera and ducking derive from it. **File:** `public/assets/models/moke/moke.glb` in metres, +Y up, facing +Z, origin on the floor between the paws; PBR materials; no Draco/meshopt/KTX2; bone, socket (`socket_mouth`…), morph (`blink`) and clip names exactly as in `MOKE_3D_SPEC.md`; locomotion in place at the game's speeds. **Behaviour:** loaded optionally (no file, no request); `GltfMokeVisual` blends clips from the model-independent animation state with a procedural layer on top; anything missing is reported and skipped; if the model is absent or unusable, `ToonMokeVisual` (D12) is used with a console warning. Personality (sit, stretch, glances via `AttentionSystem`) stays model-independent state, so both visuals show it. Keeps D7. | 2026-09-24 |
| D15 | **Mobile is the same web game, with touch feeding the same actions** | Set in Phase 3 per the owner's brief. One codebase and build; no native or separate mobile app. Touch (floating joystick, camera drag, virtual `Touch:*` buttons) goes through `InputState` like the keyboard and controller, so gameplay never branches on device. Input mode comes from capabilities plus last use, not the user-agent. Portrait and landscape both supported (a wider field of view in portrait). ~~Landscape first, with a rotate hint~~: replaced 2026-09-25 when the owner found portrait works well and may be preferred on phones; no rotate prompts, no orientation lock. **Running on touch:** push the stick past its ring (one thumb), or the RUN toggle; no hold-to-run button, which would need a third thumb. Phones get lower quality presets and dynamic resolution; desktop stays on HIGH, unchanged. A home-screen web app with a build-generated service worker, registered in production only (never on localhost unless `?sw=on`, to avoid stale-cache development). **Since 2026-09-25 (owner: too many buttons):** only the stick, the paw (interact) and pause show; holding the paw pops out Jump, Bark, Trick and Run (RUN is still there, inside the paw). Sniff has no touch button (owner: rarely used on a phone). | 2026-09-24 |
| D16 | **Sock Heist: one scripted human, an explicit state machine, and no failure** | Set in Phase 3 per the owner's brief. One placeholder human exists for Sock Heist, not a general human simulation. Behaviour (`HumanBrain`, an explicit state machine in pure logic), body (Rapier character capsule on `NavGrid` A* paths built from the room's colliders; no navigation dependency) and look (`ToonHumanVisual`) are separate, like Moke (D7). **The human never catches Moke:** grabs always fumble, and frustration always ends the chase in a treat, so there's no fail state or soft-lock. Orchestration lives in `SockHeistController` (the pattern for future mini-games), decoupled through a tiny typed `GameEvents` hub. SOCK = TREAT is recorded in `DogLogicMemory`; the full Dog Logic system is Phase 4's. | 2026-09-24 |
| D17 | **Moke can jump, but the couch seat and coffee table are the highest he can get** | Owner request (2026-09-25): "jump on top of the couch or table as the highest but he can't jump to the tv". The height cap is absolute (feet at most 0.50 m above the floor, `JUMP` in `config/movement.ts`), so jumps can't chain higher; Rapier tests pin what he can and can't reach. Controller B jumps (it was bark); bark and growl share one button (F / Y / touch Bark) and pick at random. | 2026-09-25 |
